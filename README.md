## Анализ и рефакторинг

- В исходной реализации списание, не учитывалось вычисление бонусов, т.е. складывались с типом acrual, но не вычитались сс типом spend, так же выбирались все бонусы для текущего пользователя не учитывалась дата. 
- Обернула списание бонусов в одну транзакцию с проверками, если  утекущиего пользователя было списание с данным requestId и  одиановым payload, то это списание работает и падает с ошибкой, если списание с другим payload. Добавила проверку, что бы не списывалось в отрицание, если на каком-то шаге падает ошибка, то транзакция полностью откатывается.
- На уровне бд добавила миграцию на уникальный ключ двух полей userId и  request_id
- обработка очереди реализована через retry,  в него добавлено количество дублей и интервал запуска. Сначала выбираем все записи с временем меньше текущем и типом spend. Потом проходимся по объекту и выбираем, только те id, у которых  в строке есть request_id = expire:id и добавляем их отдельный массив. Второй раз прохожим по объекту, если id записи, есть в массиве, то такую строку не добавляем в таблицу.
- Можно было реалиизовать без транзакций, используя кафку, но для этого нужно переделать архитектуру проекта
- Написала только один тест, с ними работала мало,не хватило времении дальше разобратся, чтобы написать оставшиеся тесты.
